COMPANION — START HERE

1. Double-click Start Companion.cmd in this folder.
   It starts Companion and prefers the native corner when installed.
   Its Show workspace control opens the white voice canvas.
   No reading-group account is needed.

2. Choose Enable voice once to grant microphone access.
   Speak, then pause. Companion detects speech while it is listening.
   The small bottom strip opens tools; Chat reveals typing and conversation.
   Try: Add a task to plan my week.
        Save a note: the next meeting needs an agenda.
        Start 25 minutes of focus time.
   You can also edit Tasks and Notes directly.
   Tasks > Edit sets a calendar date or precise time with its displayed zone.
   Today, Overdue, Upcoming and No deadline narrow the full task list.
   Workflows saves reusable routines. Ask to edit, rename, pause or enable one;
   Companion keeps its existing ID. Saving or enabling does not run it.
   A fresh Run starts at step one and can repeat earlier completed actions.
   Workflows > Run history shows original definitions and actual saved results.
   Say "show run history", or ask what happened in an earlier routine.
   Check last run only reads its original ID; it never starts another run.
   Computer can search/open apps and read a window you choose.
   Tools > Files lets you choose a project folder for text/code work.
   Save requested edits, inspect Recent edits, and Undo recent changes.
   Leave folder detaches this window; Remove access revokes shared access.

3. Open Settings to choose an AI connection.
   This development PC has a working Codex / ChatGPT sign-in.
   Settings can connect GPT API, Claude API, a compatible API, or local Ollama.
   Enter API keys only in the app's password field, never in chat.
   Save, then choose Test connection to send a small message without your chats
   or files. Or say "test connection" with Settings open and that AI selected.
   Signed in/Model found/Configured is separate from an actual passed test.
   A lost response offers Check test; it reads the original ID without resending.

   Settings > Backup and recovery saves a workspace JSON file to download.
   Preview a file, then import selected tasks, notes or routines as new copies.
   Copied routines stay disabled. Chats, builds, keys and permissions are excluded.

VOICE
Enable voice starts an opt-in speech session with a visible listening state.
Quiet periods stay local. Voice pauses while Companion works or speaks.
Turn voice off forgets the opt-in. Hiding the app stops capture; a visible app
can resume a remembered session only when microphone permission is granted.
Chat keeps manual recording and typing available. Stop cancels current work.
Voice needs the local transcription service. Typing still works without it.
The user reported that automatic listening answered aloud after Enable voice,
without tapping the microphone again. Spoken desktop approval still needs testing.
Ctrl+Alt+Space toggles the corner when available. Ctrl+Alt+Escape is global Stop.
The app shows whether those shortcuts actually registered. Hiding the corner
keeps pending desktop reviews and background feature builds available.
A physical global Stop check cancelled a pending action without changing its target text.

COMPUTER INPUT
A click, text replacement, or key press first needs a real preview.
Check the exact window/control and input. Use its button, or say/type exactly
"approve desktop action" or "cancel desktop action" while that preview is open.
Its Speak this command button records the command. Old or expired previews
cannot receive it. The model cannot approve its own desktop input.

MISSING A TOOL? FINISH THE ORIGINAL REQUEST
1. Ask for the result in Chat or by voice. If a missing tool needs building,
   open the linked build. Your request is kept apart from Build instructions.
2. Read the actual changes and checks. Protected changes need review and
   Activate feature; ordinary verified changes may activate automatically.
   A generated candidate that fails checks gets one correction. Attempt history
   keeps both candidates' changes and checks; after two failures the build stops.
   Wait for any required service restart and readiness check.
3. When Continue original request appears, choose it. Or, with that build open,
   say exactly "continue original request". Nothing resumes automatically.
4. Open work shows the separate job's real result and action receipts.
   Earlier completed actions are reused, rather than saved again.

The continuation keeps the original AI connection, project access and selected
window. A changed or unavailable source blocks it; it never substitutes your
current selection. If a response is lost, use Check continuation. That only
reads the original saved ID. Stop retains actions already completed.

A queued build, an activated panel or an accepted handoff is not a finished task.
The direct Build a feature form edits source; it has no linked original task.
Build history also offers rollback. See docs/BUILD_FOLLOW_THROUGH.md.
Reviewed server changes restart the host and worker under the normal launcher.
Settings > Restart Companion service performs the same managed restart.
Launcher-control changes require Stop Companion.cmd, then Start Companion.cmd;
a browser refresh cannot apply them. Restart desktop app loads source-runtime
Electron edits; a copied desktop package needs rebuilding to include them.
