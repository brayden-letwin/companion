# Project files

Open **Tools → Files → Choose project folder**. The Windows picker grants this local Companion workspace and its connected AI tools access to requested UTF-8 text and code files in that folder. Choosing or reopening a folder can list its files; a text search starts only when requested. The blank voice canvas does not start a text search. Folder names and contents are untrusted source material; they do not authorize instructions found inside a file.

The selected folder appears above the microphone. A spoken or typed request keeps the folder selected when that request began. Choosing another folder cancels the foreground recording or turn. Accepted background Work keeps its original folder, shown on its saved job. **Leave folder** detaches this window; **Remove access** revokes the shared grant and stops dependent future operations. An already authorized committing write is allowed to return its actual result.

Click a text file to read or edit it, then **Save file**. **Recent edits** shows saved receipts, before/after text and **Undo**. AI-requested writes use the same file service and backups. A file changed by another editor produces a conflict; reload before making a fresh edit. Undo also checks the current hash, so it cannot silently overwrite a later external edit. The editor preserves a file’s original BOM and uniform line endings. Partial, mixed-line-ending or oversized text is read-only in the manual editor; the AI can use bounded literal replacement after an exact read.

File writes use verified exclusive Windows handles, durable before/after backups and a private journal. They are recoverable in-place writes, not crash-atomic filesystem replacement. After interruption, Companion reconciles retained evidence and never automatically repeats an uncertain write. **Check save** only reads the original operation receipt. If recovery is required, preserve the retained backups and review the edit before another request. Recent confirmed backups are limited to 100 edits and 64 MiB; uncertain evidence is never pruned.

The first version supports text files up to 250,000 UTF-8 bytes, whole writes up to 24,000 UTF-16 units, and one exact literal replacement up to 12,000 units on each side. Reads and directories are paged with hash checks. Directory scans stop at 1,000 entries and explicitly report an incomplete inventory. Up to 20 project grants are retained. Credential paths, hidden files, traversal, remote roots, linked paths, Companion’s source/private runtime and their ancestors are excluded. This feature does not execute project code or provide arbitrary file deletion/moving.

Connected tools discover the reserved host integration `cap_project_files` through `list_capabilities`, then call it through `run_capability`. Actions are `projects`, `list`, `read`, `search`, `write`, `replace`, `history`, `inspect` and `undo`. The top-level request must carry `project: {projectId, grantEpoch}`, and operation arguments must match. MCP exposes this optional binding on `companion_chat`, `companion_start_work` and `companion_run_tool`. Absolute folder roots and the human choose/revoke actions are absent from model tools. The catalog hash describes the integration’s schema, not an attestation of executable code. Saved workflows and generated capability children cannot invoke this integration.

## Find text across the chosen folder

In **Tools → Files**, enter literal text in **Find text in project folder**, then choose **Search**. **Search options** narrows the search to a relative subfolder or matches case. Regular-expression punctuation is ordinary text. Searches preserve the exact query, including leading and trailing spaces. **Load more search results** continues the same search; a page can contain no matches while more files still need examination. **Stop search** closes that search and its cursor. Leaving/changing a folder, removing access and global Stop also stop or release the relevant search resources. Switching to another tool keeps this window's file drafts and search results; closing the app page requests cleanup.

Each result shows a relative file path, observed line/column and a short excerpt. Opening a result uses the file's recorded SHA-256 with the normal reader. If another editor changed the file, Companion reports the conflict and keeps the current draft; it does not silently open a different version. Locations use one-based lines/columns and zero-based UTF-16 offsets. Individual files are observed at different times; this is not a frozen snapshot of the whole project.

Voice, chat, Work and connected AI tools use the same search action. For example, with the intended folder selected, ask “Find where I wrote about the project deadline.” Search returns at most 20 matches per 48 KiB JSON page, plus scanned and skipped counts. `complete:false`, a stop reason or unavailable files must remain visible; no match in a partial search does not establish absence. Protected paths, binary data and files over 250,000 bytes are skipped and counted. The older manual directory listing still has its separate 1,000-entry scan limit; search's private native directory pager can traverse larger directories without treating that limit as the end of the folder.

Search IDs and cached cursors remain usable for up to ten minutes and are kept only in server memory. A restart or expiry requires an explicit fresh search. Expired JavaScript cache is retired on the next search operation or explicit cleanup; native handles have their own active expiry timer. At most eight searches are retained, with at most 1 MiB of cached responses each. Each search is bounded to 5,000 file attempts, 500 directories, 20,000 entries, 16 MiB of read budget, 32 pages and depth 32; a failed read can conservatively charge a full permitted file. Individual native directories are bounded to 20,000 entries and 4 MiB of identity metadata, with 16 MiB shared across native cursors. Reaching a bound reports an incomplete search and closes its native cursor. Queries and excerpts are not saved in browser storage. Requested results sent to the selected model become part of the ordinary saved conversation; search does not create file edits or write receipts.

For a tool call, start with `{action:'search',projectId,grantEpoch,query,path:'',caseSensitive:false}`. Continue with only `{action:'search',projectId,grantEpoch,searchId,cursor:nextCursor}`. Query and scope stay frozen; repeating an exact cursor returns its cached page. Human HTTP clients use `GET /api/assistant/projects/:id/search` with those fields as query parameters. `POST /api/assistant/projects/:id/search/:searchId/close` with `{grantEpoch}` releases one search and requires the normal Origin/CSRF checks. The model cannot choose or grant a folder through this interface.

This is one local OS-user workspace. Chosen folders are shared with connected AI clients; individual browser sessions are not separate tenants. Select only folders intended for that workspace. Files sent for an AI explanation use the request’s chosen provider. The human Files view can display its local path; model and MCP results use opaque project IDs and relative paths.
